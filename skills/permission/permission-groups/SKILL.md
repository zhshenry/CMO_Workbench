# PIC 群组创建

站点：PIC 权限管理 → 群组管理 → 群组创建。沿用当前登录分区与浏览器授权。

## 产品归属：专用工具流程

有 group_fill 工具时使用以下流程；没有该工具时，按 [页面现场参考](references/page-guide.md) 使用已有 browser_* 工具。不要调用当前工具列表中不存在的工具。

1. 将用户已明确的产品/部门归属、Offering 名称或编号、群组名称、Owner 工号、成员工号、管理员工号、应用类型直接传给 group_fill。工具先校验，缺信息时返回全部缺失项且不操作页面，再一次向用户询问；信息齐全则在同次调用内直接填写。不打开弹窗猜归属，不从组名推断 Offering。
2. 首次或修改参数时传完整建群信息，已有草稿续填可传 {} 复用当前任务参数。仅用户明确的产品归属走自动填写；工号传字符串以保留前导零，members 传工号数组。
3. group_fill 自动选择 Offering、在表格新增编辑行、填写并局部核对，跳过实际已正确填写的值。返回 ready 后直接进入 group_submit；blocked 时读取具体字段和错误，不重复从头填写或连续观察整页；本轮两次失败后说明卡点，请用户处理。
4. 仅需要重新核对进度或提交结果时调用 group_inspect，不作为每次填写后的固定步骤。已填写的表单会重新核对实际字段值；提交结果未知时只读取结果，不点击提交。
5. group_submit 在真正提交入口内部展示完整确认卡，用户确认后才点击一次“提交申请”，无需另调 declare_write。用户取消后本轮不再次请求提交。
6. submitted 表示已核验申请提交成功，不表示审批生效；unknown 表示未获取明确凭据，只能核对结果，不能重试点击提交或传新参数覆盖草稿。重名错误须先让用户明确新名字，再将完整参数传给 group_fill；不自行添加后缀。

## 已确认的业务规则

- Offering 必须由用户明确提供；同名多形态时，用户未指定形态则优先 [Offering R]，无法唯一匹配时询问。
- 前缀默认 HIS；完整名称 HIS-PACIFIC610-CODE 拆为 HIS 与 PACIFIC610-CODE，页面拼接中横线。允许用户指定其他已支持前缀与分隔符。
- Owner/管理员是单人字段；成员支持英文分号分隔，专用工具接收数组并负责填写。必须等待并选中人员候选，输入工号不代表已选中。
- DBOX 群组搭配域群组；SVN 群组搭配域群组；小网/海思只选海思群组。PDM、PMS、运营商 ALM、JDC 等须用户明确选择，不猜组合。
- 有效期默认两年，支持一年、两年、三年；不寻找日历。
- 核验输入框实际值和已选标签；正文缺少人员或名称值不代表未填写。描述长度上限仍需现场核对，不把历史旁证当作已验证限制。

## 部门、批量与页面变化

- 部门选择器尚未校准，部门任务沿用当前通用浏览器流程，参见 [页面现场参考](references/page-guide.md)。
- 批量导入使用平台模板；文件上传由用户手动处理。
- 表头、编辑行或人员候选不唯一时停止自动填写，保留进度并说明问题，不猜列号或盲点。
- 成功回执的真实 PIC 页面形态仍需现场校准。专用工具仅在当前页面出现包含目标群组名的明确提交成功凭据，并通过浏览器核验后报告 submitted。

## 通用浏览器流程的提交确认

仅使用 browser_* 工具的部门/批量等流程，提交、保存、删除前仍必须调用 declare_write 并等待确认。专用 group_submit 已在内部执行确认，不重复弹确认卡。
