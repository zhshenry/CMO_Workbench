# PIC 群组创建页（权限管理 → 群组管理 → 群组创建）

> 本 skill 指导如何在该页创建权限群组。页面会改版，使用前先 observe 确认实际结构。
> 标注「待实测」的部分尚未验证，使用时以现场 observe 为准。

## 站点与入口

- 站点：https://productinfo.huawei.com/#/main/right_manage?menu_id=3232（PIC 平台）
- 面包屑：首页 / 权限管理 / 群组管理 / 群组创建
- 顶部主导航含：CMO事务处理 / 权限管理 / 代码管理 / 配置库管理 / 版本管理 等，本页在「权限管理」下。
- 登录态：走华为 SSO，网页工作台 permission-groups 分区内已隔离保存。

## 页面结构（已实测，2026-11-04）

页面自上而下：

1. **归属选择区（产品/部门二选一，含级联）**：顶部先选群组归属类型——「产品」或「部门」：
   - 选「产品」→ 还需继续选择 **offering 信息**（级联选择）。
   - 选「部门」→ 还需继续选择 **部门信息**。
   - 两条路径后续表单不同，AI 必须先确认用户要建的群组归属类型，再走对应分支。

### Offering 信息选择弹窗（产品路径，已实测 2026-11-04）

选「产品」后弹出**「请选择Offering信息」对话框**：

- **状态过滤**：Active / Inactive / Disable / Obsolete 四个单选项（默认 Active），切换状态重新加载 offering 列表。
- **Offering 列表**：每条格式为 `[组织前缀] 名称 编号`，如 `[IRB] 重量级团队 11111111`、`[Offering R] NGSF V800 266363689`。
  - 实测组织前缀类型：`[IRB]`（重量级团队/研究院/业务IRB）、`[IPMT]`、`[BMT]`、`[TDT]`、`[PDT]`、`[SPDT]`、`[LMT]`、`[TMT]`、`[LV2/LV3 Unclassified]`、`[Offering]`/`[Offering V]`/`[Offering R]`（版本/形态变体）。
  - Active 状态下约 130+ 条，无分页（一次性长列表）。
- **行选择**：点 offering 行选中，选中反馈为**整行高亮**（非复选框/单选圆点；2026-11-04 实测选中 `[Offering R] PacificEng V600 266756442`）。【单选/多选未实测，按 UI 形态推断为单选】
- **同名陷阱**：同名 offering 可能存在多个形态变体，仅方括号前缀不同——实测同一列表中同时有 `[Offering] PacificEng V600`、`[Offering V] PacificEng V600`、`[Offering R] PacificEng V600 266756442`。**用名称文本定位会命中多行报 ambiguous-locator**，必须带组织前缀或编号精确定位。
  - **选择优先级（用户规则）**：同名多形态并存时，**优先选 `[Offering R]`**；用户未明确指定形态时按此默认，不必反问（用户明确指定其他形态时除外）。
- **选中反馈**（2026-11-04 实测）：点「确定」后弹窗关闭、DOM 残留清除，选中的 offering 回填到顶部「产品」选择器。**注意：回显值在纯文本流里不可见**（渲染在 select/cascader 输入框的 value 中），核验"是否选好"要看表单元素的 value 状态，不能靠正文文本；回填不触发下方群组列表刷新（列表仍「暂无数据」属正常）。
- 弹窗浮层挂在 `body` 末尾（Element-Plus dialog 结构），observe 时注意它在 frames/elements 列表的最后，不要遗漏；弹窗关闭后列表 DOM 会有残留，以可见性判断为准。
2. **添加方式 tab**：「单个添加」/「批量导入」二选一。

### 单个添加（已实测 2026-11-04）

点「单个添加」**不是弹表单，而是在表格里新增一行行内编辑记录**：

- 表格新增 1 行（序号 1），总数从「共 0 条」变「共 1 条」，底部出现「暂无数据」消失。
- **群组名称列自动预填 + 前缀选择（已实测 2026-11-05）**：点击单个添加后，名称会随所选 offering 自动带出（offering 名即群组名基调）——**但名称不是纯文本，还带一个前缀选择**：群组名称 = **前缀（下拉选择）+ 名称主体（随 offering 预填）**。
  - 前缀下拉可选值（11 个，实测）：`CSI` / `HIS` / `TC` / `TTELab` / `CHEI` / `CRI` / `CMTI` / `RCC` / `APRI` / `SED` / `ERI`
  - **前缀为必填项**（下拉内提示「群组名称前缀为必填项」），不选无法提交。
  - **前缀与名称拆分规则（用户规则，2026-11-05 确认）**：
    1. 前缀**默认选 `HIS`**，用户未指定前缀时用 HIS，不反问。
    2. 用户提供完整群组名时要**拆分**：如用户说「HIS-PACIFIC610-CODE」→ 前缀下拉选 `HIS`，名称主体填 `PACIFIC610-CODE`；**前缀与主体之间的横线不用管**（页面会自动拼接），不要把横线带进名称主体，也不要把前缀重复填进主体。
    3. **命名建议**：原则上建议用户用 `-`（中横线）作为名称内部分隔符；用户有其他诉求（下划线等）也允许，不强制。
  - AI 操作时不要把名称当纯文本整体处理：先选前缀，名称主体随 offering 自动带出后按需调整。
- **群组描述**：普通文本输入（待顺路确认有无字数限制）。
- 新行各列为可编辑控件，占位符「请选择」标示待填项：群组名称（随 offering 带出）、群组描述、群组Owner、群组成员、群组管理员、群组应用类型、有效期。
- **群组应用类型（已实测枚举 + 用户规则）**：多选下拉（勾选式），下拉下方有提示文案「勾选应用类型后，代表可以在对应的应用系统中使用该群组」。8 个可选值：
  `DBOX群组` / `SVN群组` / `海思群组` / `域群组` / `PDM群组` / `PMS群组` / `运营商ALM群组` / `JDC群组`
  每个选项对应一个下游应用系统，一个群组可同时勾选多个。
  - **选择规则（用户决策规则，2026-11-05 确认）**：
    1. 用户要 DBOX 群组 → 勾选 `DBOX群组` + `域群组`（两项）。
    2. 用户要 SVN 群组 → 勾选 `SVN群组` + `域群组`（两项）。
    3. 用户要小网或海思群组 → 只勾选 `海思群组`（单选）。
    4. 其他情况（PDM/PMS/运营商ALM/JDC 等）→ **先向用户提问确认**，不要自行选择。
  - **回显形态（2026-11-05 实测）**：勾选后在单元格内以**多个独立 tag 并排**显示（如 `DBOX群组`、`域群组` 各一个 tag），AI 核验时逐个 tag 检查，不是拼接文本；有效期回显为选项文本（如「两年」）。
- **人员字段（Owner/成员/管理员，用户实测口述 2026-11-05）**：**没有人员选择弹窗**——直接在单元格输入框里**输入工号，系统自动匹配**（输入联想/自动补全）。
  - 操作方式：点击单元格聚焦 → 输入工号（如 `00545972`）→ 等系统匹配出人员结果 → 选中匹配项回填。
  - AI 操作要点：用 fill/pressSequentially 输入工号后**等待联想结果出现**（browser_wait 或 locator 动作），不要输完就跳走；从联想列表里选中匹配项才算完成，回填后单元格显示人员信息（姓名+工号）。
  - **隐形坑（2026-11-05 实测确认）**：①输入框里的工号是 input 的 value 属性，**纯文本流观察不可见**——核验"是否已输入/已回填"要查表单元素的 value 状态，不能靠正文文本；②**人员三列（Owner/成员/管理员）填写后的回显同样在提取层隐形**（已实测：页面肉眼可见回显，但文本流/表格行提取读不到）——AI 核验人员是否填好必须走表单元素状态（无障碍树 value/tag），正文里看不到不代表没填；③**群组名称的主体同样隐形**（实测：名称「HIS-TEST」中前缀 HIS 在下拉层可读，主体 TEST 在 input value 层读不到）——核验名称主体是否已填须查 input 的 value；④联想结果浮层是瞬态 popper（Element-Plus 结构），随焦点收起——AI 操作节奏上必须"输入 → 等联想 → 选中"三步走，不能连续快速操作。
  - **群组成员与 Owner/管理员的差异（用户口述确认 2026-11-05）**：同样是输入框自动联想，但成员框**支持一次输入多个工号，用英文分号 `;` 分隔**（如 `00545972;00514659`），输入后系统对每个工号分别自动联想匹配。Owner/管理员为单人字段。
  - AI 操作要点：批量添加成员时把多个工号用英文分号拼成一串填入即可，**不必逐个输入**；注意必须是**英文分号**（不是中文全角 `；`），拼串前先校验分隔符。
- **有效期（已实测 2026-11-05）**：**不是日期面板**，是下拉快捷选项，三个可选值：
  `一年` / `两年` / `三年`
  选中时长后系统自动计算起止日期。AI 不要去找日历控件或输入具体日期，直接从三个预设时长中选择即可；**用户没指定时长时默认选「两年」**（用户规则，2026-11-05 确认），无需反问。
- 操作列有「删除」「复制」两个行级按钮：删除移除该行，复制新增一行同配置记录。
- 可连续点「单个添加」新增多行（多群组一次申请）。
3. **工具条**：「下载模板」按钮（批量导入用）、「已选：N 删除」（列表多选删除）。
4. **群组列表表格**，列序（从 0 起）：
   0 复选框 | 1 序号 | 2 群组名称 | 3 群组描述 | 4 群组Owner | 5 群组成员 | 6 群组管理员 | 7 群组应用类型 | 8 有效期 | 9 操作
   - 列表为空时显示「暂无数据」「共 0 条」。
   - 分页：默认 10 条/页。
5. **底部动作条**：「保存草稿」「提交申请」「取消创建」。
   - **按钮使用规则（用户规则，2026-11-05 确认）**：三个按钮中**原则上只点「提交申请」**（正式提交走审批）；「保存草稿」「取消创建」不是常规路径，仅在用户明确要求时使用。

左侧导航树（实测）：权限配置（系统权限配置/配置库权限配置/权限回收）、权限查询（常规查询/权限推荐/权限看板）、**群组管理（群组创建/群组变更/群组成员合法性排查）**、CMO权限交接、权限审核/变更。

## 操作流程

### 创建单个群组（主路径）
1. **确认归属类型**：先问清用户群组挂在「产品」还是「部门」下——这决定后续级联选项和表单分支，不能默认走产品。
2. 选归属类型并完成级联选择：产品 → offering 信息；部门 → 部门信息。
3. 切到「单个添加」tab。
4. 逐列填写行内编辑行：前缀（默认 HIS）+ 名称主体、描述、Owner、成员（分号分隔）、管理员、应用类型（按选择规则勾选）、有效期（默认两年）。
5. **提交前必须用户确认（强制）**：点击「提交申请」前，**必须先用 `declare_write` 向用户弹出确认卡片**（intent 如「创建群组」，target 填群组全名），等用户在卡片上确认后才能点击「提交申请」。用户取消时不得点击。
### 提交反馈（实测中）

**失败场景（已实测 2026-11-05）——组名重复**：

- 提交「HIS-TEST」时因组名已存在被拒，弹出**「提示」对话框**：
  ```
  保存失败！失败原因： ['HIS-TEST']以上组名已存在iright,请修改
  [确定]
  ```
- **关键信息**：
  1. 错误反馈是**模态弹窗**（标题「提示」，带「确定」按钮），不是 toast——出现后必须点「确定」关闭才能继续操作。
  2. 失败原因格式：`['组名1','组名2']以上组名已存在iright,请修改`——**组名带方括号引号列出**（多行提交时可能列多个组名），AI 解析时要提取括号内的组名清单。
  3. 「已存在 iright」说明**提交时系统会向 iRight 校验组名唯一性**——群组名在 iRight 侧全局唯一。
  4. 失败后**表格行保留**（填写的所有内容不丢失），可改名后重新提交。
- **AI 处理流程**：提交后若弹出此错误 → 读出失败的组名清单 → 向用户报告并建议改名（如加后缀 `-1`、`-NEW`）→ 用户确认新名后改名称主体 → 重新走 declare_write 确认 → 再提交。
- **预防**：提交前如担心重名，可先用「权限查询」页（group.iright.huawei.com）搜索同名群组预检。

**成功场景**：待实测。

### 批量导入
1. 切到「批量导入」tab。
2. 点「下载模板」获取 Excel 模板，按模板填写。
3. 上传填好的文件。文件选择是 `manual-required` 场景（driver 会拒绝代传文件），需用户手动完成。

## 已知坑（element-blocked 高发区，已实测确认）

- **右下角悬浮「海问思答」AI 助手浮窗**（hiwen.huawei.com）：常驻悬浮在页面右下区域，会遮挡附近的表格操作列/底部分页。操作右下区域元素时若报「元素被其他内容遮挡」，先看是否被该浮窗盖住——可先收起浮窗或滚动让目标离开右下角。
- **表格加载遮罩**：切产品/tab 后表格刷新会有 loading 遮罩，此时点击表格行/按钮会报遮挡。用 locator 动作（timeoutMs ≥ 5000）自动等待，或先 browser_wait 再操作。
- **报错已增强**：element-blocked 的报错会带出遮挡元素的标签/class/文本（如 `<div.el-loading-mask>正在加载…`），据此判断遮挡来源再决策，不要盲目重试。

## 写操作必须先确认（强制）

- 「提交申请」「保存草稿」「删除」都是写操作，会改变平台数据，不可撤销。
- 执行前**必须先调 `declare_write`**（intent 如「创建群组」「提交群组申请」；target 填群组名称），等用户确认后才能点击。
- 「取消创建」会丢弃本次会话的填写内容，同样按写操作对待。
- 切 tab、选产品、下载模板、浏览列表是只读操作，无需 declare_write。
