# CMO 的 AI 原生工作区第一阶段开工单

2026-11-20 · 方案稿 · 与 OnoSan 同期开工

第一阶段在 CMO 交付“选中办公事项 → 办公助理准备待办 → 人确认并改期 → 助理读回实际日期”。OnoSan 同期实现总管看板的双向编辑并修正待办回执。CMO 可以依靠本仓现有事务回执、建议卡和办公材料服务直接开始。后续阶段与共同规则见[双仓总体方案](../../../../../onosan_workbench/docs/requirements/shared/ai-assistant/ai-native-workspace-parallel-plan-2026-11-20.md)。

## 开工任务

1. **固定测试输入。** 使用隔离数据，准备两个同名、来源不同的办公事项。将测试时钟设在周一，使“本周五”和后来手动改的“本周四”都有确定日期。把两连接交错写入补入回归。Bot 提交后、回执返回前，由第二连接新增人工事项，断言库里有两条而 Bot 回执只含它实际写入的那条。现有事务内对象返回是基线。[待办 Store](../../../../modules/todo/store.ts) · [现有回执测试](../../../../tests/todo-store.test.ts)
2. **把当前选中项带进普通对话。** 在用户明确指向“这条”或从待处理事项发起时，冻结发送时的办公事项 ID、来源 ID 和账号范围。执行端用当前账号解析对象和来源。选择已变、换账号、有多个候选或对象失效时，返回具体对象状态，必要时给出选择。[办公界面](../../../../src/views/OfficeView.tsx) · [办公材料服务](../../../../electron/office-workbench.ts)
3. **让两个入口准备同一个建议。** 复用现有办公建议生成、Host 去重和主对话确认。新增仅向相应工作区及任务暴露的工具，按办公事项 ID 取来源并接纳用户明确给出的日期。首次由聊天发起时关联原工作。已有待确认建议且内容相同时定位原卡，用户补充日期时更新该卡并使旧确认版本失效。来源消息保留原文。[办公 Bot 适配器](../../../../electron/cmo-bot-adapter.ts) · [Host 的建议准备逻辑](../../../../electron/bot-host.ts) · [现有入口权限](../../../../electron/bot-service.ts)
4. **从业务对象续接。** 确认后以实际待办 ID 建立办公事项关联。办公助理沿该关联获取必要的日期和完成状态。原任务已经写入后再改期，按已有待办修改规则针对同一条记录处理。Bot 和人工操作的结果都呈现在相关界面。[现有关联读取](../../../../electron/bot-host-entry.ts) · [办公业务与确认行为](../../../../UX-CONTRACT.md)
5. **同期盘点七个预制工作区。** 从总管、日程、办公、权限、交付件、PBI、DTS 的真实页面逐项登记用户动作、GUI/Bot 入口、权威数据、资源范围、确认及成功凭据。交付件与 DTS 按已接入来源标记，PIC 的人工接手和正式提交分开登记。

## 本仓交付验收

| 操作 | 应看到的结果 |
| --- | --- |
| 选事项甲发送请求，随即切换到同名事项乙 | 原建议仍指向甲。切到无权账号时原引用失效。 |
| 先点按钮生成建议，再在对话补充日期 | 只有一张可确认的有效卡。旧版本不能批准。确认前正式待办写入数为零。 |
| 用户确认，重复点击或重连后再核对 | 业务库只有一条对应事项，回执里有实际待办 ID、日期和可核对的记录版本。 |
| 用户在日程界面把周五改成周四，再回到办公助理询问 | 读到周四，可定位原来源和同一条待办。 |
| 在同一个临时事项库做交错写入、过期版本更新及事务中断 | 回执仅含本次对象。过期修改不会覆盖新值，回滚后没有成功回执。 |

现有[办公事项用例](../../../../tests/office-workbench.test.ts)和[办公场景用例](../../../../tests/office-assistant-expansion.test.ts)可扩充这条流程。交付物为本仓功能、定向测试结果、隔离 Electron 演示和能力清单。记录使用的工作树版本、对象与回执及验证环境。[隔离数据说明](../../../../README.md#规范与数据)

## 双仓合验与随后工作

用同一份临时库让两个产品的 Store 各写一条，交换对象与回执断言，并各演示一次“人 → Bot → 人”。两边都通过时记录第一阶段联合结果。随后 CMO 补总台看板全套布局动作、办公状态操作，以及从已填网页字段接手 PIC 表单。自定义 Bot 使用验证过的资源绑定和执行权限。[办公领域设计](office-materials-and-bot-workspaces.md) · [PIC 表单工作流](../../../../modules/permission/group-workflow.ts)
