# PIC 群组创建

站点：PIC 权限管理 → 群组管理 → 群组创建。沿用当前登录分区与浏览器授权。

## 产品归属：专用工具流程

根据用户描述的群组归属和办理方式选择工具。「我们部门要建一个产品群」属于产品单建。单个产品群组使用 group_fill。部门归属、批量导入或用户明确要求通用浏览器时，按 [页面现场参考](references/page-guide.md) 使用 browser_* 工具。用户只问用法时直接回答。

1. 将用户已明确的归属、Offering 名称或编号、群组名称、Owner 工号、成员工号、管理员工号、应用类型传给 group_fill。单个建群未说明归属时，保留 ownership 空缺，请用户补充。产品建群缺项时先校验，信息齐全才填写。收到 waiting_information 时，原对话已展示补全卡，等待用户回答后按原任务继续。其他入口返回 needs-information 时一次问齐缺项。归属和 Offering 以用户明确提供的信息为准。
2. 首次或修改参数时传完整建群信息，已有草稿续填可传 {} 复用当前任务参数。仅用户明确的产品归属走自动填写；工号传字符串以保留前导零，members 传工号数组。
3. group_fill 在网页的 Offering 弹窗里匹配候选，找不到时用弹窗搜索框。然后新增编辑行、填写并核对，跳过已正确填写的值。ready 表示表单已填好。「先填好让我看看」或「只预填」时保留表单并结束本轮。用户明确要求提交申请或完成建群时，才调用 group_submit 发起确认。补全参数本身不表示用户要求提交。blocked 时按返回的字段和错误处理，本轮两次失败后向用户说明卡点。
4. 仅需要重新核对进度或提交结果时调用 group_inspect，不作为每次填写后的固定步骤。已填写的表单会重新核对实际字段值；提交结果未知时只读取结果，不点击提交。
5. group_submit 在真正提交入口内部展示完整确认卡，用户确认后才点击一次“提交申请”，无需另调 declare_write。用户取消后本轮不再次请求提交。
6. submitted 表示已核验申请提交成功，不表示审批生效；unknown 表示未获取明确凭据，只能核对结果，不能重试点击提交或传新参数覆盖草稿。重名错误须先让用户明确新名字，再将完整参数传给 group_fill；不自行添加后缀。

## 已确认的业务规则

- Offering 必须由用户明确提供；同名多形态时，用户未指定形态则优先 [Offering R]，无法唯一匹配时通过原对话中的结构化选择卡询问，保留全部已读取候选的完整名称和编号；用户选择后续接原草稿，不猜测、不默认选第一项。
- 前缀默认 HIS；完整名称 HIS-PACIFIC610-CODE 拆为 HIS 与 PACIFIC610-CODE，页面拼接中横线。允许用户指定其他已支持前缀与分隔符。
- Owner/管理员是单人字段；成员支持英文分号分隔，专用工具接收数组并负责填写。必须等待并选中人员候选，输入工号不代表已选中。
- DBOX 群组搭配域群组；SVN 群组搭配域群组；小网/海思只选海思群组。PDM、PMS、运营商 ALM、JDC 等须用户明确选择，不猜组合。
- 有效期默认两年，支持一年、两年、三年；不寻找日历。
- 核验输入框实际值和已选标签；正文缺少人员或名称值不代表未填写。描述长度上限仍需现场核对，不把历史旁证当作已验证限制。

## 部门、批量与页面变化

- 在补全卡选择「部门」并点击「进入通用流程」，原任务会在原群组创建标签继续。先用通用浏览器工具核对实际部门入口，缺少部门信息时再请用户补充。新版页面的部门入口仍待实测，无法确认时说明卡点并保留已有参数。 [页面现场参考](references/page-guide.md)
- 批量导入使用平台模板；文件上传由用户手动处理。
- 表头、编辑行或人员候选不唯一时停止自动填写，保留进度并说明问题，不猜列号或盲点。
- 成功回执的真实 PIC 页面形态仍需现场校准。专用工具仅在当前页面出现包含目标群组名的明确提交成功凭据，并通过浏览器核验后报告 submitted。

## 通用浏览器流程的提交确认

通用浏览器流程按用户要求预填或办理。用户明确要求执行提交、保存或删除时，调用 declare_write 并等待确认。页面工具要求人工提交时，请用户在原网页操作，之后核对实际结果。专用 group_submit 在工具内部发起一次确认。

- 填写、搜索与打开下拉属于自动办理步骤，记录在处理记录中，不逐步请求用户核对网页。ready 的字段校验仅证明表单填好；提交成功必须有包含本群组名称的明确回执，汇报“申请已提交，待审批”。
