# CMO 的 AI 原生工作区第一阶段开工单

2026-11-22 修订 · 与 ONOSAN 并行开发，分机部署

双仓的单一发送、自动改向、工作记录和总管看板已通过本地实窗验收。CMO 第一阶段接下来交付“选中办公事项 → 办公助理准备同一张待办建议 → 人确认并改期 → 助理读回实际日期”。从本仓已有事务回执、建议卡和办公材料服务继续。共同进度与后续任务见[双仓待做功能清单](../../../../../../onosan_workbench/docs/requirements/shared/ai-assistant/rel006-ai-native-workspace-and-human-bot-handoff/plan.md#六待做功能清单)。

## 开工任务

1. **固定测试输入。** 使用隔离数据，准备两个同名、来源不同的办公事项。将测试时钟设在周一，使“本周五”和后来手动改的“本周四”都有确定日期。本仓已通过双连接回归。用本仓独立隔离库验收安装版，每份回执只含本次实际写入的对象。[待办 Store](../../../../../modules/todo/store.ts) · [现有回执测试](../../../../../tests/todo-store.test.ts)
2. **把当前选中项带进普通对话。** 在用户明确指向“这条”或从待处理事项发起时，冻结发送时的办公事项 ID、来源 ID 和账号范围。执行端用当前账号解析对象和来源。选择已变、换账号、有多个候选或对象失效时，返回具体对象状态，必要时给出选择。[办公界面](../../../../../src/views/OfficeView.tsx) · [办公材料服务](../../../../../electron/office-workbench.ts)
3. **让两个入口准备同一个建议。** 复用现有办公建议生成、Host 去重和主对话确认。新增仅向相应工作区及任务暴露的工具，按办公事项 ID 取来源并接纳用户明确给出的日期。首次由聊天发起时关联原工作。已有待确认建议且内容相同时定位原卡，用户补充日期时更新该卡并使旧确认版本失效。来源消息保留原文。[办公 Bot 适配器](../../../../../electron/cmo-bot-adapter.ts) · [Host 的建议准备逻辑](../../../../../electron/bot-host.ts) · [现有入口权限](../../../../../electron/bot-service.ts)
4. **从业务对象续接。** 确认后以实际待办 ID 建立办公事项关联。办公助理沿该关联获取必要的日期和完成状态。原任务已经写入后再改期，按已有待办修改规则针对同一条记录处理。Bot 和人工操作的结果都呈现在相关界面。[现有关联读取](../../../../../electron/bot-host-entry.ts) · [办公业务与确认行为](../../../../../UX-CONTRACT.md)
5. **同期盘点七个预制工作区。** 从总管、日程、办公、权限、交付件、PBI、DTS 的真实页面逐项登记用户动作、GUI/Bot 入口、权威数据、资源范围、确认及成功凭据。交付件和 DTS 的业务接入、纯人工 PIC 表单接手按待定登记。PIC 已有流程按实际动作登记。

### 第一步的对话改向

与 OnoSan 同期验证发送和业务接续，复用上面“办公事项 → 建议 → 实际待办”的对象与回执。待定的乐高区方案见[双仓工作计划](../../../../../../onosan_workbench/docs/requirements/shared/ai-assistant/rel006-ai-native-workspace-and-human-bot-handoff/plan.md)。

1. 普通发送立即入原会话。CMO Host 保存客户端消息 ID、发送时的办公选中项、来源、账号与原确认卡；能确定的操作直接处理，需要语义消歧时交 Pi 作只读判断，Host 再核验候选、任务版本及授权。对“改周四”“下午三点”按顺序改同一工作。确认前旧建议失效，已提交的写入先等原回执，再按同一待办 ID 改期。补充在原子任务上生效。
2. 主聊天默认显示业务结果与必要的确认、登录或失败。用户可以主动查看当前工作的执行依据和经脱敏的工具记录。自动改向与消息可靠回显通过后，在同一批转为一个发送入口。主对话里的操作回执、确认、待回答和站点授权使用同一个紧凑卡片。可点卡片标题查看本次操作，也可从 Bot 名片查看整项工作，两个入口共用执行记录。

11 月 21 日已在办公助理的隔离 Electron 窗口验证连续三句归入同一工作，以及两个共用记录的入口。实窗使用本机模拟模型。待办确认、改期与回执另经本地数据库回归。发送时绑定办公选中项、来源和账号范围，以及用普通聊天从原来源发起或修订建议，列入本阶段剩余事项。

### 总台看板

总管和右侧看板使用同一份已保存布局。CMO 目录包含「日程和待办」和「AI 额度」。接手续作以已保存的卡片与版本为准，验收用日程和待办从堆叠图改为对比图，保留用户刚保存的位置。参见[双仓总管看板实现](../../../../../../onosan_workbench/docs/requirements/shared/ai-assistant/rel006-ai-native-workspace-and-human-bot-handoff/plan.md#总管看板的双仓实现)。

## 本仓交付验收

| 操作 | 应看到的结果 |
| --- | --- |
| 快速发送改期和时间、在另一个窗口打开原对话，再重复提交同一条客户端消息 | 两次补充各显示一次，收敛成同一目标和一张有效建议；旧轮的输出与写入不能覆盖它。 |
| 用户刚点确认时说“改周四”，以及在查询实际回执期间重启 | 原消息保留。按原操作核对、关联真实待办后修改同一条；无需用户重发。 |
| 选事项甲发送请求，随即切换到同名事项乙 | 原建议仍指向甲。切到无权账号时原引用失效。 |
| 先点按钮生成建议，再在对话补充日期 | 只有一张可确认的有效卡。旧版本不能批准。确认前正式待办写入数为零。 |
| 用户确认，重复点击或重连后再核对 | 业务库只有一条对应事项，回执里有实际待办 ID、日期和可核对的记录版本。 |
| 用户在日程界面把周五改成周四，再回到办公助理询问 | 读到周四，可定位原来源和同一条待办。 |
| 在 CMO 的隔离事项库做交错写入、过期版本更新及事务中断 | 回执仅含本次对象。过期修改不会覆盖新值，回滚后没有成功回执。 |

现有[办公事项用例](../../../../../tests/office-workbench.test.ts)和[办公场景用例](../../../../../tests/office-assistant-expansion.test.ts)可扩充这条流程。交付物为本仓功能、定向测试结果、隔离 Electron 演示和能力清单。记录使用的工作树版本、对象与回执及验证环境。[隔离数据说明](../../../../../README.md#规范与数据)

## 双仓合验与随后工作

CMO 与 ONOSAN 分机部署。两仓各用自己的隔离事项库验证安装、升级、回执和人机接续。同一开发机的共库测试用于本地兼容检查。当前阶段跟进办公事项接手，后续计划包含办公状态操作和 PBI 只读用例。乐高区与客户跟进台、自定义 Bot、纯人工 PIC 表单接手、交付件和 DTS 业务接入待定。[办公领域设计](../office-materials/spec.md) · [PIC 表单工作流](../../../../../modules/permission/group-workflow.ts)

## 乐高区候选方案（待定）

在办公助理里增加独立于浏览器和终端的乐高区。让 Pi 编写“客户跟进台”的实际 HTML、CSS 和 JavaScript，选中事项提交到现有待办确认。随后修改应用代码以按来源分组，保留选择和原对象。宿主提供受限源码工具、本地预览与工作区业务接口；固定构建器验证 React/TSX 样例。CMO 保留原有 WeLink 业务命令的授权范围。

验收时从自然语言生成源码，人选中一项后由 Bot 处理。改布局或重启都能定位原来源，错误版本回到上一版。再用 TSX 样例检验随包编译。
