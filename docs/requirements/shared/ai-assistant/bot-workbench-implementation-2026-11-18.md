## Bot 名片、资料库和工作台

主窗口固定模式先显示当前 Bot 的对话。顶部悬浮名片始终在对话正文这一列居中。名片右侧的箭头朝右时可展开资料侧栏，展开后箭头朝左，再点一次即可收起。侧栏与对话共用一张卡片，中间以细线分隔。侧栏沿卡片右缘滑入、滑出，和对话平移共用 240ms 的缓动。连续点击时从当前位置折返。系统开启「减少动态效果」时立即切换。点击左侧联系人切换对话，右键、菜单键或 Shift+F10 打开只有「编辑 Bot」的菜单，选择后进入该 Bot 的详情。

Bot 回复靠左，用户消息靠右。短消息随内容收宽，主对话长气泡最宽 560px。开合左侧联系人或右侧资料栏时，两侧气泡随留白水平移动，同一条消息保持原来的断行和阅读位置。宽表格和代码在气泡内横向滚动。

在主窗口的「详情」或「资料库」中，单击头像下方的名称或简介即可原位编辑。按 Enter 或点击文字下方的「保存修改」提交当前资料草稿，简介用 Shift+Enter 换行。Esc 撤销本次聚焦以来的编辑，「取消修改」撤销整份资料草稿。保存后同步更新联系人与对话名片。如果另一窗口已更新资料，侧栏显示最新版本，用户确认后只合并本地改过的字段。点击顶部头像，在头像正下方的浮层切换角色、图形和颜色。「重置」恢复当前 Bot 的默认头像预览，「保存修改」提交资料草稿。点击浮层外或按 Esc 可收起并继续浏览当前页。「详情」可以选择模型。记忆、工作进度、定时任务和历史对话均从详情进入。「资料库」在原侧栏切换为当前 Bot 的交付件，支持预览、查看来源任务和打开可用原件。

点击「工作台」收起资料侧栏，并在对话卡片外的右侧展开这个 Bot 对应的业务工作区。之后仍可从名片查看资料库或进度。关闭工作台后继续原对话。侧栏在宽窗中占 280–340px，卡片宽度不超过 800px 时，资料栏在卡片内覆盖正文，顶部名片仍可收起侧栏并返回原来的阅读位置。草稿和已打开的工作区继续可用。

各 Bot 从共用的供应商和模型列表中选择自己的模型。侧栏显示模型名和供应商，展开分组后用勾号标记已选模型。底部的「模型配置」直达设置里的对应页面。普通对话、委派、只读询问和后台执行使用执行 Bot 保存的模型。未选择模型或已选模型被删除时，Bot 等待选择。升级时，原来跟随默认的 Bot 会一次性保存此前所用的模型。旧版遗漏的绑定会重新补齐，读取不到有效旧模型时等待下次启动重试。已有选模和全新安装的选模由各 Bot 管理。Host 通信版本为 v9，AI 数据库版本为 6。

## 与 OnO 一致的 AI 行为

- 联系人拥有稳定头像、颜色、职责、工作说明、私人／共享记忆和定时任务；右键或 Shift+F10 打开菜单，选择「编辑 Bot」进入资料侧栏。角色、图形各 12 个，与 10 种颜色独立组合。
- 固定模式左侧为对话、右侧为工作区，悬浮模式的输入、答复和展开动效、全局收起均使用来源实现。主窗口不同模式共享同份草稿。灵动岛与主窗口共享总管消息，各自保留未发送输入。
- 已发消息与收到消息都能点击／Enter 进入双方的连续记录；在原左侧区域展示，返回不丢草稿，不改变右侧工作区。思考与工具详情折叠时不预先渲染正文。
- 工作进度按任务、等待及实际结果展示；交付件保存 Markdown，并能追到来源任务。这里的“交付件”是 Bot 产物，不代表已接通 CMO 项目交付系统。
- 同一 Bot 的模型任务顺序执行，Host 最多并发两个模型任务。等待确认、其他 Bot 或资源释放模型槽位；已确认的业务写入保留执行状态直到回执返回。
- 补充要求通过安全边界停止旧轮并继续处理，未实现 Pi 原生 steer。迟到的旧工具调用、旧确认和旧结果不覆盖新要求。
- 流式消息按条目增量同步，序列缺口或 Host 重启后重新核对；不是每个 token 重发整段历史。仍采用来源的每轮释放 SDK 策略，不宣称已解决来源所有持续使用卡顿。

CMO 的必要差异仅在身份、领域工具与产品环境：六个 CMO Bot、原事项日期 v4、W3／SSO、WeLink、PIC 和权限／PBI 浏览器保留。浏览器执行使用实际模型的图片支持标记。配置保存事件优先于迟到的初次读取，避免第一次配好模型又被旧空配置覆盖。CMO 原有设置弹窗覆盖草稿的保护和旧入口空回复错误保留。

## 写入与浏览器资源

1. 待办建议仍经过用户选择、事务和版本检查，保留原日期语义。
2. WeLink 查询白名单直接执行；其他命令将 service、subcommand、完整 args 与指纹持久保存，返回“等待确认”。确认只执行原参数。取消无外部写入；无明确业务成功回执则保留原始输出并标待核对，不自动再次执行。
3. PIC `group_submit` 保留原校验和表单，在持久确认后重新核对并提交；参数变化产生新确认。已提交不代表审批通过。失去原浏览器资源且尚未提交时进入可恢复的资源等待。
4. 浏览器 WebContents 仍归 CMO 主窗口，Host 通过资源桥调用；Bot、模式切换不卸载原浏览器。连续 PIC 补充沿用原流程；同业务的人类上下文可以延续，旧 DOM 引用和工具调用不重放，跨领域委派不继承私有聊天历史。
5. 通用 `browser_act` 继续受现有任务、标签和站点边界约束，但自动保存、回车提交等尚无全面自动写入识别；`declare_write` 仍需要模型按规则调用。不能声称“全应用所有写操作都有统一 Hook”。
6. 业务结果未知、执行时断开或重启时在途的动作保留待核对；取消不撤回已经发出的操作，迟到回执可以保存但不复活已取消任务。正常退出会等待已确认写入的回执收尾。

## 运行、数据与迁移

- 正式数据属于 `%APPDATA%/CMOWorkbench`；OnO 的 Bot、会话、凭证、记忆与运行目录不复用。共享 `%APPDATA%/To-Do-List/tasks.db` 只用于原事项业务，不迁移或改写共享库的 chats/settings。
- Bot 表与原 AI 会话同在 CMO 的 `chats.db`；Pi 日志在 `bot-sessions/<botId>`，任务工作目录在 `bot-runtime/<botId>`，产物在 `bot-artifacts/<taskId>`。
- 迁移先 `VACUUM INTO` 留下 `chats-before-bots-*.db` 一致快照，再事务绑定旧对话。按原始 scope 归属，保留原 ID、消息和草稿；未知类型、设置历史和损坏记录保留查阅，不猜成待办。首轮 Bot 方案及通信升级均有迁移保护；遇未来不支持版本停止而非重建数据库。
- 回滚须先停止 CMO 主窗口和 Host，另存当前 `chats.db` 及 WAL／SHM 后，使用迁移前快照配合原版代码恢复；回滚不会自动合并迁移后的新增消息。不删除原库或备份，不通过降版本号强行兼容。
- 默认主界面启动一个独立 Host，收起至托盘继续；未开独立后台时退出应用会停止它。`设置 → 通用 → 独立 Bot 后台` 由用户明确开启后才注册当前用户的 Windows 托管任务，登录后待命并支持重启恢复。
- 独立后台只代表本机进程存活，不代表电脑休眠／关机后继续。没有主窗口浏览器资源时，浏览器任务等待资源；共享模型关闭或未配置时不调用模型。系统托管注册链路已接入，但本次未为真实用户注册计划任务或验收实际登录自启。
- 两个 Electron 进程复用同一 OS 保护的加密身份，等待主进程加密状态落盘后再启动 Host；不导出明文密钥。开发、构建、安装入口均进入 `bootstrap.ts`。

## 协作回执与续答（v8）

总管发出委派后，“已发消息给 助理”跟在交接回复下方。助理回传结果后，“消息来自 助理”出现在下一段总管回复上方。每段分别记录时间、思考、正文和工具调用。点击收发提示可在原对话区定位双方往来。

Host 在投递事务中记录待处理的回信 ID。续答启动时，把这些 ID、来源和接收 Bot 与新消息一并写入，同时将回信标为已消费。旧流式消息保留已有正文，尚在运行的旧工具标记中断。旧版已经覆盖的中间文本无法还原。

待办确认在写入事务内收集实际新增或更新的事项，按提交后的 ID 和字段把结果回传总管。待确认时主工作继续等待协作。失败或中断的工具调用单独计数，工作进度使用任务自身的状态。开发模式完整退出并重开后会尝试正常替换空闲的 v7 后台，处理中或排队的旧后台会提示等待。
