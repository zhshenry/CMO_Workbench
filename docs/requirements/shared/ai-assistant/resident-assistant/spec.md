## 1. 目标

同一个助手始终在工作台中可用。首次打开时关联当前页面；切换左侧一级工作台时自动恢复该工作台上次选中的对话，无历史则显示新对话；同工作台内切换页面仍保持当前对话。标题行显示助手图标、“AI 助手”和右侧收起按钮；下方独立协助对象卡固定在消息滚动区之外。卡片主行显示模块与本次协助对象与范围说明；待办与日程不重复显示对象名。下行依次放工作区标签、历史对话选择器和新建对话 ＋。添加参考仍在输入区，可选择其他待办或书目作为只读参考。同一工作台沿用当前对话，跨工作台由导航自动恢复上次选中的对话或进入新对话。各条对话分别保留聊天与未发送的草稿。

## 2. 已确认方向

| 项目 | 方案 |
|---|---|
| 全局入口 | 顶栏保留 36px 单图标 AI 按钮，所有页面位置相同；填充图标与浅色底提示展开状态，悬停显示名称 |
| 展开方式 | 足够宽时右侧并排停靠；主内容仍可同时操作 |
| 常驻含义 | 助手与会话由应用外壳持有，页面切换不卸载运行任务；面板允许主动收起 |
| 展开偏好 | 正式应用记住展开状态和宽度 |
| 何时联网 | 主动发送或点击明确的 AI 快捷指令时调用；导航、选对象、展开面板均不自动请求模型 |
| 当前对话 | 协助对象卡下行依次显示工作区标签、紧凑会话选择器和新建对话 ＋；选择器只显示真实会话标题，长标题单行省略，常态无填充底色。菜单贴着选择框展开并按可用空间避让，支持搜索、工作台筛选及历史管理；可用工作台即使没有历史也保留空分组，点空态才建立该工作台的通用对话，不切换页面。卡内 ＋ 是常驻新对话入口，历史对话可重命名；删除操作原位变为“确认删除”，再次点击才删除。范围说明在卡片主行的信息按钮悬停或键盘聚焦时显示 |
| 上下文切换 | 同工作台切页保留当前对话；切换一级工作台自动恢复对应对话，若无历史则显示新对话，首次发送时创建。切换业务对象时自动更新下一轮对象，不新建对话；顶部协助对象卡显示本轮对象并可固定，固定状态在本次运行中按对话保留。通用页面不会覆盖原有业务对象 |
| 添加参考 | 输入区独立列出所选参考，可移除；弹窗以名称和更新时间区分对象。最多选择 8 个同类参考，主对象不重复列入。AI 通过 `read_reference` 按所选 ID 读取，不能访问未选对象；写入建议仍只针对主对象 |
| 写入 | 沿用建议 → 确认 → 应用；原内容发生变化时重新核对 |
| 首版生成并发 | 同时一个生成任务，可跨页继续；另一会话可浏览和输入，发送暂不可用 |

正式应用采用 **380px 初始宽度、340–480px 可调整范围**。分隔条可拖动，也可聚焦后按左右方向键调整。

## 3. 空间分配

### 宽窗与默认窗口

顶栏沿用当前 54px 胶囊，左侧一级图标栏沿用 66px。主体为当前内容与 AI 两列，间隔 16px；两列分别滚动，助手标题、上下文与输入区固定在各自位置。

正式助手顶端与顶部胶囊下沿留 16px 间距，底端距窗口 12px；长对话在助手内部滚动，输入区固定在底部。消息区始终预留滚动条宽度，避免滚动条出现时让消息卡片重新换行。

输入框底部提供紧凑操作栏，右侧放模型选择和发送按钮，不另占一行面板空间。

展开和收起采用 220ms 的淡入淡出与轻微横移；宽窗口的主内容和二级目录占位同步收放，窄窗口仅面板过渡。减少动态效果设置下立即切换。

开启助手时，固定二级目录收起；悬停或键盘聚焦左侧工作台图标时，在图标旁展示对应工作台的二级目录。收起助手时保留当前工作台的固定目录，其他一级图标仍可悬浮或聚焦展开二级目录，当前一级不重复弹出；浮层覆盖在固定目录上方，不挤动页面，选择子页后才导航。一级导航始终保留。

助手采用现有 `--ai-panel-bg` 实底，避免后景文字透入。保持深色主按钮、克制的雾蓝强调，沿用三主题、字体和 18 / 14 / 10 圆角体系。

### 最小窗口

助手在工作台容器小于 **1160px** 时改为右侧覆盖抽屉，不继续压缩主内容。抽屉仍为非模态，保留左侧导航和顶栏入口；不盖全屏遮罩，不锁住整页，也不设置错误的模态焦点陷阱。

- 收起按钮、顶栏入口、Escape 都可收起，焦点回到入口。
- 点击正文不自动关闭，避免切换操作时反复丢失助手。
- 正式实现的停靠判定应看剩余主内容宽度与页面最低可用宽度；1160px 是初始验证值。

## 4. 会话与对象

“当前对话”采用协助对象卡下行的紧凑快速切换下拉：默认显示最近 4 条（当前对话不在其中时保留其入口），搜索覆盖全部会话，工作台筛选始终列出可用工作台；空工作台可在空态开始通用对话，不切换页面，也不自动读取业务对象。卡内 ＋ 是唯一常驻新对话入口；历史搜索、筛选和管理统一由下拉菜单承载。下拉内可重命名对话，删除操作原位变为“确认删除”，二次点击才删除且不能恢复，点别处或失焦取消。一个工作台允许多条对话；同一条对话可跨这个工作台的页面继续；同工作台切页保留对话和未发送输入，默认跟随新的编辑对象；仅在发送时读取对象的最新资料。切换一级工作台自动显示该工作台上次选中的对话，无历史则显示新对话。旧会话按其原始对象归入所属工作台，不合并消息。

“新对话”在当前选中的工作台和关联范围下创建。顶部协助对象卡主行显示本次协助对象和模块；待办与日程不重复显示对象名。卡内信息按钮在悬停或键盘聚焦时显示详细范围，下行显示工作区标签、会话选择器与新建入口；切换一级工作台时直接恢复该工作台对话，无历史则在首次发送时创建。若新页面只有通用帮助能力，原来明确关联的业务对象仍是本轮对象；页面名称只作为导航上下文，不凭工作台归属扩大读取与写入权限。若新页面带有业务对象，则改为本轮对象。

发送时以本轮对象重新读取最新内容，并校验其仍属于这条对话的工作台。Agent 提示词区分工作台、本轮业务对象、明确关联的页面和来自其他对象的历史消息；每条消息记录发送时的对象与页面。首页待办允许跨日延续；通用页面没有业务写入工具。页面上的 AI 快捷指令进入其工作台当前对话，并明确关联触发它的对象。

同一对话可以添加其他对象作为只读参考。每轮只在提示词列出所选参考的 ID 和名称，内容由模型调用 `read_reference` 按需读取；未选对象和其他工作台的对象无法通过此工具读取。待办参考提供标题与详情；书目参考提供书名、作者与已记录状态。发送记录保存本轮参考列表，打开对话时恢复最近一轮的选择；尚未发送的参考调整在本次运行中保留。参考已删除时明确报错，可移除后重发。主对象切成某份参考时，该对象自动从本轮参考中排除。

有待确认建议时切页或切换工作台，建议留在原会话。不同对象的建议分别保留，只有同一对象的新建议替代旧建议；应用按钮标明目标对象。导航不自动放弃建议，也不把它应用到新对象。

## 5. 任务生命周期与恢复

| 操作 / 状态 | 用户可见行为 |
|---|---|
| 发送 | 输入进入当前会话，展示生成状态与停止按钮；面板以正常聊天方式定位最新内容 |
| 生成时切页 | 页面正常切换，原任务继续；顶栏显示原对象与“生成中”，点击可返回 |
| 在新页面输入 | 同工作台保留当前对话和输入，下一轮对象可随页面改变；已有任务运行时发送不可用，并解释原因 |
| 后台完成 | 结果写回原会话，顶栏显示原对象与“已完成”，不强制打开面板或抢焦点 |
| 收起 | 保留输入、消息、建议和运行任务；打开后继续原状态 |
| 停止 | 中止生成、保留已收到内容与可重发输入；不会应用半成品建议 |
| 请求失败 | 保留问题及已有内容，原位给出重试；不清空整段对话 |
| 应用建议失败 | 保持待确认或冲突状态；成功后才显示已应用 |
| 目标已删除 | 标记原对象已不存在，历史可读，禁用写入，不能改绑到当前的新对象 |
| 应用退出 | 正式接入后恢复历史，未完成任务标记中断并允许重发，不假装继续生成 |

每次请求固定会话、模块、对象、选区和本轮内容版本。回包按请求绑定归位，不再查“此刻页面在哪”。

首版只保留一个生成槽位，降低从现有单 `activeRequest` 实现演进的复杂度。页面能自由切换，与多会话并发执行是两件独立的能力。

## 6. 正式接入的最小改造边界

实施基线：`src/App.tsx` 持有全局 `AiPanel`、页面上下文和后台状态；`electron/ai-ipc.ts` 维护单个运行请求与按会话保存的待确认操作。

| 层 | 调整内容 |
|---|---|
| 应用外壳 | 统一停靠 / 覆盖布局；持有展开、宽度、页面上下文和后台任务提示 |
| 页面接入 | 各工作台分别上报业务对象；选区属于本轮上下文 |
| 会话 | 按工作台管理对话，逐轮记录业务对象、页面和参考列表；已有无 module 历史仍按原待办逻辑兼容 |
| AI 内核 | 沿用模块贡献机制；根据会话所属模块装配上下文与工具 |
| 请求与建议 | 将运行状态和待确认建议关联到会话与对象；切页不清除其他对象建议；写入时重检目标版本 |
| 业务存储 | 待办仍走现有共享 tasks/categories；AI 配置与聊天仍为工作台独立存储 |

现已按上述边界接入，正式运行合同同步记录在 `DESIGN.md` / `UX-CONTRACT.md`。

## 7. 评审与验证

评审重点：380px 对话阅读是否舒适；目录收起后是否好找；对象名称是否足够醒目；窄窗覆盖是否可接受；建议卡是否能让人放心确认。

应验证：

1. 各工作台的上下文、记录与未发送输入分别恢复。
2. 待办的确认 / 保留 / 撤销，内容改动后的冲突提示。
3. 生成时切页、后台完成后返回、停止生成。
4. 同对象新对话与历史恢复，不同对象不串话。
5. 三主题、1280×820 与 1024×680、收起后扩展主内容、分隔条键盘调整。
6. 核心文字与操作不发生横向溢出；长聊天内部滚动，输入框和收起入口可达。

正式应用以类型检查、构建、测试和启动冒烟验证；真实模型输出仍取决于用户配置的供应商与模型。
