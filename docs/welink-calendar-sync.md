# CMO 双来源日程同步

2026-11-16。范围为通过现有 CLI 读取邮箱日历及 WeLink 会议，统一供自动同步、手动刷新和 AI 查询使用。外部内容保持只读，CMO 完成状态独立保存。

## 使用

在「设置 → W3和Welink接入」登录 WeLink，使用「立即同步」，或开启「会议日程同步」后按既有间隔轮询从今天起的 30 个自然日。两路查询成功后，在同一范围内自动核验新的会议配对，每轮最多补读 5 条候选邮箱日历详情。「日程待办 → 日程」切换日期时，按当前日／周／月视图读取对应范围（月视图仅取实际月份）。日期工具栏左侧的「刷新外部日程」可手动读取当前范围。悬停按钮可查看各来源的同步状态和失败原因。

「邮箱日历」卡片展示当前账号的日历连接状态。默认复用 CLI 现有连接；明确缺少 EWS 配置时，优先使用绑定到登录账号的已保存地址，否则从 `onebox user-info` 读取本人邮箱。配置成功后重试原查询一次。自动配置未完成时显示折叠的「手动配置邮箱」，可保存当前账号的企业邮箱后立即重试。旧版未绑定账号的地址需要在手动配置时重新确认。普通网络或登录错误不会触发邮箱发现。

邮箱日历、WeLink 会议分别显示本次状态和更新成功的时间。一处失败不阻止另一处更新；失败来源保留缓存，有缓存时会标明，悬停可查看上次成功时间和失败原因。只有两个来源均成功并完整查询且结果为空，才可解释为没有安排。

连接失败时区分 WeLink 桌面客户端未打开、需要扫码和暂时无法检查。CMO 运行时复查随包 CLI 的凭据，临期或过期先在后台尝试续期，完成后重新核验登录状态。遇到扫码提示即停止当次后台尝试，原凭据仍有效时可继续读取。自动读取从 30 秒（临时失败）或 60 秒（客户端未连接或需要扫码）开始退避，最长 10 分钟。日程页跟随连接状态并保留当前日期范围的缓存。确认恢复后立即补读从今天起的 30 个自然日，并接着读取之前受阻的当前日期范围。

## 代码所有者

| 内容 | 位置 |
|---|---|
| CLI 参数、响应验证、分页、限流 | `electron/welink-agenda.ts` |
| 本地合并、事务、完成状态、缓存与详情 | `electron/welink-sync.ts` |
| 公共来源、标识、结果与时间范围 | `shared/welink-agenda.ts` |
| 邮箱配置及来源状态 | `shared/contracts.ts`、`SettingsView.tsx` |
| 轮询、手动刷新及详情 IPC | `electron/desktop-island.ts` |
| AI 统一查询和详情工具 | `modules/welink/ai-tools.ts` |

AI 优先调用 `welink_agenda(start,end)`，结束日期不含当天，最多 31 天。轮询窗口内复用刷新结果，其他日期使用相同适配器查询，不清理另一个窗口的数据。结果中的 `cached` 标明来源未成功时保留的缓存。`events` 保留原始记录，`displayEvents` 按同账号、不同来源、同全天属性、规范化标题相同及起止各 60 秒容差一对一合并；两条结束时间都缺失时也可匹配，只有一条缺失时不匹配。展示组含 `primary` 与原始 `sources`，优先以日历为展示项；展示和场次计数使用展示组。详情工具按 calendar 来源的 `taskId` 读取；正文作为数据，不作为执行指令。

2026-11-17 增加同类界面合并：日程列表、首页计数、顶栏与灵动岛只显示一场，并标记「WeLink + 日历」。它只是标题和时间启发式，不是已核验的共享事件身份。两条来源身份和原始记录独立保存。

2026-11-18 起，同账号的两条来源必须各自只有一个符合标题、起止时间和全天属性的候选，且有完整有效的起止时间，才共用一份 CMO 提醒、稍后提醒与完成状态。任一来源稍后才同步到，也继承已有的本地处理状态。匹配不明时独立处理，均不修改远端。

## 已确认的响应

用户提供了两个日历列表项、一份详情和一份会议列表样例；均已校验 JSON 可解析。项目参考和测试仅保存虚构数据，不复制真实会议正文、员工信息、原始 ID 或入会链接。

| 来源 | 列表结构 | 标识／版本 | 时间 |
|---|---|---|---|
| 邮箱日历 | 顶层数组 | `itemId`／`changeKey` | 带时区的 `start`／`end`；`isAllDay`、`isCancelled` |
| WeLink 会议 | `code=200`、`data.data[]` | `meetingId`；会议号另存 | `meetingStartTime`／`meetingEndTime`，毫秒数字或数字字符串 |

日程右侧在选中会议后按需加载详情。邮箱日历使用 `calendar get` 补充地点、组织者、参会人、正文和入会链接，且保留匹配到的 WeLink 会议号。只有 WeLink 来源时，使用列表取得的 `meetingId` 调用 `meeting info`，可打开返回的原始详情或纪要链接。两种详情失败时都保留列表字段，并可单独重试。详情按账号、记录和版本缓存，最长 10 分钟。只开放来源返回的 HTTP(S) 链接，原始详情和纪要链接与入会操作分别呈现。邮箱正文请求 Text 并按纯文本呈现。

仓库自带 CLI 1.0.16 的实际参数解析拒绝 `calendar --format json`，因此日历命令不带该选项，直接验证输出是否为 JSON。不能根据 `--help` 的退出结果断言该参数受支持。

```text
# 仅明确缺少连接配置时：welink-cli mail autodiscover --email me@example.com
welink-cli calendar --tz "China Standard Time" list --start 2026-11-16 --end 2026-11-17 --max 500
welink-cli calendar --tz "China Standard Time" get --item-id <ItemId> --body-type Text
welink-cli meeting info --meeting-id <meetingId>
```

## 完整性和本地更新

- 两个来源独立读取。会议系统的独有安排也进入日程；跨来源显示与本地提醒联动不改变记录身份；不能把链接参数、会议号、标题或相同时间当作 `meetingId`。
- meeting 查询待参加（1）和范围内已结束（2）会议，按最多 30 条翻页。实测材料中 `total=0` 与非空数据并存，因此不以 total 判断结束；短页／空页结束，重复页、页数上限或异常数据均报告不完整。
- calendar 按日查询，覆盖跨午夜事件；单日达到 500 条视为可能截断。成功退出时的 `No events found.` 表示当天为空，并继续读取后续日期。未知结构、缺字段、非法时间、重复 ID 对应不同实例起点时报告不完整，保留该来源旧记录，不猜测周期规则。
- 账号身份来自 CLI 的 UID；日历属于当前登录账号，可选发现邮箱不参与记录身份，避免填入或清空提示后出现重复。兼容旧邮箱后缀命名空间并保留已有 ID 与完成状态；同步前后核对身份，期间切换账号或邮箱则放弃本轮落库。旧 `welink:<meetingId>` 仅在读到相同会议时补齐标识并保留完成状态；未归属的旧历史仍保留，不擅自绑定账号。
- 每轮以事务更新已验证的记录。只允许完整来源清理同一账号、同一窗口内缺失的记录；失败、不完整、窗口外和历史记录不因没查到而移除。明确取消的日历事件可标记移除。本地完成、创建时间和未变化时间对应的提醒认领保持。
- 429 最多重试两次（1 秒、2 秒），其他错误交给来源状态。自动／手动刷新共用进行中的请求；CLI 请求串行，避免多源突发调用。
- 日期查询按中国时区统一构造左闭右开范围；meeting 的毫秒结束参数转换为结束零点减 1 毫秒。全天显式显示「全天」，跨日事件按时间重叠出现在相关日期。

## 验证边界

此前本机的只读查询提示 token 过期且 refresh token 无效，真实邮箱连接未完成验收。登录凭据由 CLI 管理，CMO 不自行读取 credentials.json。自动检查使用脱敏虚构返回和隔离数据库；原生窗口用进程内 CLI 夹具验证完整 IPC、设置和页面流程。周期及全天样例不等于真实服务全覆盖：全天与跨日已用夹具验证，真实周期实例仍需补充核验。服务未暴露明确跨系统关联字段，因此保留两处原始记录；新增的合并显示可能误匹配或漏匹配，不作数据身份保证。
